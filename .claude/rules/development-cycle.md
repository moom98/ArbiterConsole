# Development Cycle Rules

開発は、以下のサイクルを繰り返しながら進めてください。

## 基本方針

一度に大量の実装を行わず、機能または論理的な変更単位ごとに、

**実装 → テスト・静的チェック → レビュー → 修正 → 再レビュー**

のサイクルを実行してください。

可能な限り、実装を担当したエージェント自身ではなく、**別のサブエージェントにコードレビューを担当させてください。**

実装担当とレビュー担当の役割を明確に分離してください。

---

## 開発サイクル

各タスクについて、以下の順番で進めてください。

### 1. 実装前確認

実装する前に、関連する以下の情報を確認してください。

- 要件定義
- 設計資料
- CLAUDE.md
- 既存コード
- 関連する型定義・API仕様
- テストコード

不明点があっても、既存資料やコードから合理的に判断できる場合は作業を止めずに進めてください。

要件と実装方針が矛盾する場合は、要件を優先してください。

---

### 2. 実装

機能を、レビュー可能な小さな単位で実装してください。

不要なリファクタリングや、今回の要件と無関係な変更は行わないでください。

実装後は可能な範囲で以下を実行してください。

- TypeScript type check
- lint
- unit test
- 関連テスト
- build

失敗した場合は、レビューに進む前に原因を確認し、実装起因の問題であれば修正してください。

---

### 3. 別エージェントによるコードレビュー

実装完了後、**別の reviewer サブエージェントを起動してレビューしてください。**

レビュー担当には、原則としてコードを変更させないでください。

レビュー対象は今回の変更差分と、その変更を理解するために必要な周辺コードです。

レビューでは最低限、以下を確認してください。

- 要件を満たしているか
- 設計と矛盾していないか
- ロジック上の不具合
