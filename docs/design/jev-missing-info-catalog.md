## 表の見方

- **区分**：
  - B = blocking（必須）
  - C = conditional（条件を満たし、かつ DT がその分岐に来たときだけ必須）
  - O = optional（任意）
- **回答**：
  - YN = はい／いいえ／わからない
  - 選択 = 選択肢＋わからない（「複数」は複数選択可）
  - 時間 = m:ss または わからない
  - 数 = 数値 または わからない
  - 構造 = 構造化データ
  - 設定 = アプリの設定・記録から取得し、質問しない
- **Jev**：報告文に明示されているかを Jev で判定する対象か（○）。
  - 端末内だけで使う fact（🔒）、設定から分かる値、fair-play は対象外です。
- **共通の fact**（`game.*`）：
  - 定義（質問・回答の形）は1つです。
  - 区分と適用条件は、使うカテゴリごとに各節の表で定めます（fact-model §2.1 の `FactUsage`）。
- **根拠**：
  - `§nn` = 要件の節
  - `DT:xxx` = 決定木の質問 ID
  - `IC§n` = `docs/design/incident-classification.md` の節
  - FIDE の条番号は、実装時に `docs/reference/rules/fide` と照合します。

**`game.history` の入力と検証（ADR-014 §4）：**

- 入力元は次の3つです。
  - その対局の `Game.pgn`（大会で記録している場合）
  - アービターが貼り付けた PGN／棋譜
  - 将来の手順入力 UI
- 端末内で検証し、検証を通ったものだけを使います。
  - 最初から最後まで合法手として再生でき、曖昧な表記がないこと。
  - 再生後の最終局面を画面に表示し、アービターが盤上の局面と一致することを確認できること。
- 手順の解釈は**厳密**に行います（chess.js の `strict: true`）。曖昧な表記や標準でない表記は受け付けません。FEN の列だけの入力は受け付けません。
- **検証に失敗した場合や履歴がない場合**は、自動判定をしません。「盤上で手順を再現して確認してください」という手動の流れに切り替えます。
- **開始 FEN から始まる履歴（途中からの履歴）**では、開始局面より前の局面が分かりません。
  - そのため、「条件を満たした」（例：同じ局面が3回出現した）は確定できます。
  - 「条件を満たさない」は確定できず、手動再現に回します。
  - 開始 FEN の halfmove clock（50手の数え始め）は入力値なので信用しません。

**DT-006 自動ドローで使う局面情報（すべて `game.history` から求める）：**

- 5回同一局面：同じ局面が5回出現したか。局面は、手番・キャスリング権・アンパッサンを含めて比べます。
- 75手：75手のあいだ、ポーンの移動も駒取りもなかったか（150 ply）。
- 75手目の手がチェックメイトだった場合は、チェックメイトが優先されます（FIDE 9.6.2）。chess.js で判定します。

`game.history` がない場合は、`dr.manual-reconstruction` を使います。
